# 按日期、按用途的事实读取规则

规则版本：`rees46-date-quality-v1`。适用解析契约：`rees46-events-v1.0.1`。本规则在本轮实现及真实读取前冻结；阈值是本项目的保守工程选择，不是行业统一标准。

## 身份与核验前提

逻辑批次身份为 `source_id + scope_id + input_sha256 + contract_version`，运行身份 `run_id` 不参与判断新输入。一个分析序列固定来源、抽样规则及种子。只有已登记、完成收据有效、独立全字段/重复重数核验通过的不可变事实批次可读。登记保存实际 Parquet 文件清单、字节数与 SHA256，以及完成收据指纹；均只留本机。读前重新核对这些证据，文件、收据、schema、scope 或记录数不符则拒绝整个请求。

同一逻辑输入的合格复验只返回已选批次，不追加；同一序列中相同内容改 scope、逻辑身份冲突或日期覆盖冲突都拒绝，不自动替换。登记用本地串行原子文件替换；不承诺并发写入或分布式事务。

## 日期和用途

| 条件 | count 用途 | amount 用途 |
|---|---|---|
| 收据、独立核验、记录守恒、身份或文件校验失败 | 整个请求拒绝 | 整个请求拒绝 |
| 批次有无法归属日期的缺失/非法时间 | 全批次日期阻断 | 全批次日期阻断 |
| 请求日期不在批次声明范围，或没有观察到记录 | 拒绝；不补成零事件日 | 拒绝 |
| 日期内时间、用户 ID、未知行为有任一核心异常，或 event_eligible 不等于记录数 | 当日阻断；不以过滤后子集代替全日 | 当日阻断 |
| 核心检查通过 | 放行所有 event_eligible 行 | 还须下列金额条件通过 |
| 购买金额缺失/非法/非有限/负值/超精度/超小数位，或 partial_observed / unknown | 保留计数及购买用户 | 阻断完整观测金额用途；不补零 |
| complete_observed，且所有购买行 amount_eligible、购买金额坏值计数均为 0 | 放行 | 放行 |
| no_purchases，且日期有记录、计数通过、购买行为/金额合格行数均为 0 | 放行 | 允许当前已核验范围的结构性零购买 |

核心异常首版零容忍。被阻断日期没有“允许范围内删掉的异常行”：读取直接失败；报告同时列出原始行数、event_eligible 数及核心不合格行数。无法归属日期的异常留在批次统计，影响整批日期可信性，不能从质量表中悄悄消失。

品牌、品类代码、session、商品/品类 ID 缺失或格式异常单独 warning，不阻断当前总体事件/用户计数与观测购买金额。后续维度分析须保留 unknown 档，不能猜测补分类。非购买行为金额问题只警告；view/cart 零价格与购买金额异常分开。真实零购买金额合法，独立列出，不等于缺失。完整观测金额仅指该候选范围内金额字段完整，不证明平台真实收入或上游日志绝对完整。

## 读取端执行

`FactReader.read(dates, purpose, expected_scopes=...)` 先验证登记、不可变证据、日期覆盖及用途规则，再返回受控 DataFrame。用途仅支持 `count` / `amount`。多日期请求有一个日期不合格就整体拒绝，不静默跳过。两种用途均保留全部合格行为记录和 `event_eligible` / `amount_eligible` 两个标记；amount 用途不会预先过滤购买行，后续分母仍完整。消费者须显式用 amount_eligible 计算金额。

日期输出包含两个放行布尔值、status、reason_codes、warning 计数、scope、源 run、契约/规则版本及核验依据。历史 `data_quality_daily.csv` 的 `formal_analysis_release=not_granted` 不改写。本轮放行表示满足 T1.1 数据使用条件，不表示 T1.3/T1.4 正式指标已验收，也不把 user_sample_candidate 升级为最终范围。

## 本轮验证范围

两份真实收据先核对；选择既有逐日质量表引用的首个成功运行 `month-v101-01`，`month-v101-02` 仅作历史复验。人工测试先覆盖用途分离、核心异常、缺失日期、无购买、收据错误和同分析序列跨月追加/防重复/失败隔离。真实事实只作一次必要的读取核对；不重解析 CSV、不重建事实表，不据此声称排除所有上游漏数。
