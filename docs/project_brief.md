# 电商增长分析与实验可信性验证

冻结日期：2026-09-16。任务：T0.1。run_id：`bootstrap-20260916T085801Z`。

## 项目目标

围绕电商行为日志建立可核验的指标，解释金额、购买率和行为路径的变化；用离线方法校验与独立公开实验来源数据评估分析方法，为业务核查和下一轮实验提供依据。

这是个人公开数据项目。当前只有规划、范围文档与环境检查，所有数据处理、业务分析、实验和性能结果均为 `not_run`。文档中的交付物是 `planned`，不代表已经具备对应实践成果。

项目名称按 `plan_v4.md` 固定为“电商增长分析与实验可信性验证”。本地文件夹沿用“电商实验分析与指标异动诊断平台 ”，原名末尾有一个 U+0020 空格，本轮不重命名。

## 本轮与首版范围

本轮授权仅包括 S0 仓库初始化、T0.1 范围冻结、T0.2 只读环境检查，以及 T0.3 的 Git 子项进展记录。拟用仓库为 `CC-GATESBY/ecommerce-experiment-diagnostics`，可见性必须为 private。仓库实际状态以执行收据为准。

本轮不安装依赖、不下载数据、不启动 Hadoop、不编写分析模块，也不执行 Spark smoke。没有数据输入，实际处理行数不适用，业务结果 `not_run`。

后续首版仍以本地小批量为当前范围。REES46 2019-10/11 和 Criteo v2.1 保留为两条独立的计划数据线；具体样本、来源许可、文件版本和输入规模要在后续任务核验。全量月份、双月全量和其他扩量均由用户以后决定，不能因小样本通过而自动执行。旧 Temu 手册不作为本轮执行规格。

## 三类证据

| 证据线 | 计划回答的问题 | 结论边界 | 当前状态 |
|---|---|---|---|
| REES46 原始行为日志 | 哪些指标、日期、路径与切片发生变化 | 只支持观察性描述；购买事件不等于订单，日志购买金额不等于财务收入，不能据此断言策略造成增长 | planned / not_run |
| REES46 离线 A/A、效应或故障注入 | 指定数据、指标与设计下，分析方法是否校准、能否识别已知变化 | 模拟与故障数据放在独立空间；不能证明线上分流、曝光系统或实际策略有效 | planned / not_run |
| Criteo v2.1 修正版 | 公开实验来源基准的组间差异、实验评估方法；后续可选增量排序 | 保留发布抽样和适用范围限制；不能还原广告主真实收益，不能解释为补贴政策效果 | planned / not_run |

两份数据不连接用户、不虚构共同平台或业务身份。可以复用统计接口、质量规则和报告格式。REES46 用于行为问题，Criteo 用于独立实验来源基准，二者证据不能相互替代。数据版本和条款的当前核验留在 T0.4，本轮未下载或验收数据。

## 口径与资源约束

- 原始区不可变；来源文件、哈希、范围与每次运行登记后再处理。
- 时间用 UTC，金额从字符串解析为 Decimal；缺失购买金额不填成真实 0。
- 候选重复和高频 session 先标记，不默认删除；文件重跑不得累计重复结果。
- 事实表不使用 `collect()` / `toPandas()`；用户表也必须先做实际内存预算。
- 观察变化、代数贡献、解释假设与因果效果分开记录；方法没有改善也是有效研究结果。
