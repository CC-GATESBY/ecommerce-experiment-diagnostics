# REES46 整月固定用户候选样本规则

规则冻结日期：2026-09-16。本轮仅准备输入，产物标为 `user_sample_candidate`；不代表已通过正式业务质量门禁或 T1.5 扩量验收。原来的两份头部 100,000 条 `engineering_sample` 原样保留。

## 先固定选择条件

唯一输入是现有清单内的 2019-Oct.csv，父 SHA256 为 `fedd938409b5f836ec89b39c861b13dad99fc7cd9beb1fddd97a2d50488b5b80`。由 `data/manifest.json` 和本地接入配置定位，不重新下载或解压。期望窗口为 `[2019-10-01 00:00:00 UTC, 2019-11-01 00:00:00 UTC)`，这不是预填的实测覆盖范围。

对 CSV 解析后的原始 user_id 字符串执行：

```text
payload = "rees46-user-sample-v1|20260916|" + user_id
digest = SHA256(payload 的 UTF-8 字节)
h = int(digest 的前 16 个十六进制字符, 16)
selected = h < (5 * 2**64) // 100
```

种子固定为 `20260916`，算法版本固定为 `rees46-user-sample-v1`，目标用户选择概率约 5%。不使用 Python hash()，不因结果调整种子或比例，不把日期、月份、会话或购买结果放入选择条件。未来获准增加月份时仍沿用相同规则。scope_id 可以标注本轮月份及父文件哈希，但不改变入选条件。

空字符串、仅含空白的 user_id 不参与抽样，分别计数并汇总为“缺失或不可使用”。除此之外，不改变 ID：保留前导零、前后空格、大小写与其他字符。非 ASCII 数字串和带前导零的非空 ID 分别记录格式提示，仍按原始字符串参与抽样。不会把它们修造成其他编号。

选中用户在本源文件内的所有可解析 CSV 记录均保留，包括重复候选、其他行为类型和价格、时间等异常字段。所谓完整轨迹仅指**本源文件内的记录**，不代表平台全部历史。空值、字段字符串及源记录顺序不变；固定使用 UTF-8、LF、QUOTE_MINIMAL 重新序列化九字段 CSV，表头仅写一次，不额外插入来源列。

## 扫描与异常处理

使用严格 CSV 解析器逐记录扫描，物理换行不是数据记录计数依据。表头必须与登记的九字段一致；字段数不等于九、CSV 引号结构错误或 UTF-8 解码失败时停止，保留失败收据和已扫描进度，不登记完整源统计或候选样本。

event_time 按源约定的精确 `YYYY-MM-DD HH:MM:SS UTC` 格式解析，并验证日期及时间是否合法。空串或纯空白计为时间缺失；其他不能按该格式解析的值计为解析失败。时间只用于覆盖统计，不改写字段、不据此过滤选中记录。窗口外可解析记录也保留并单列计数。

统计完整记录数、九字段表头、字段数异常、可解析 UTC 最早/最晚时间、每日/每小时计数、实际行为类型计数、时间异常、ID 异常与逐字段空串数量。列出期望日期中未观察到记录的日期。每天有记录只证明观察到覆盖，不能证明上游完全没有漏数。全量不同用户数不计算，记为 `not_measured`。

## 验证、资源与失败状态

先通过人工小数据和旧测试，再扫描真实源文件。源文件先做完整字节 SHA256 校验，CSV 扫描时再次同步计算哈希；扫描前后核对源大小及修改时间。选中记录写入运行专属 staging，重新读取后验证每个 ID 的哈希条件、记录数、字段顺序摘要、序列化内容 SHA256、时间统计、每日和行为类型计数。样本不同用户数使用本地 SQLite BINARY 主键精确统计，每批最多 4096 个 ID，缓存 4 MiB；不维护全量用户集合或完整事件列表。

新增输出限制为 10 GiB，SQLite 最多预留 256 MiB，元数据及日志预留 16 MiB；开始前按整个输出预算预留至少 150 GiB 空闲，运行中再次检查。输出超限时失败，绝不截断为“完整月份”。每处理 1,000,000 条记录打印数量、选中数量和耗时。受控异常、Ctrl-C 或 SIGTERM 会保留失败收据；强制杀进程可能只留下部分文件，但没有完成收据的产物绝不能登记有效。

验证成功后只将一份候选 CSV 移入专属输出目录，禁止覆盖旧目录。跨进程复现用人工小文件验证，不为真实整月样本强制生成第二份副本。全量源的用户数未测，所以只能报告“目标用户概率 5%”和“实际事件抽取比例”，不能把后者写成实测用户比例。
