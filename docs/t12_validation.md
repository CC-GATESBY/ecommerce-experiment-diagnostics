## 实现、资源与复跑

核心逻辑在 [duplicate_candidates.sql](../sql/quality/duplicate_candidates.sql) 和 [session_profile.sql](../sql/quality/session_profile.sql)，Python 入口为 [run_quality.py](../scripts/run_quality.py)，人工测试为 [test_quality.py](../tests/test_quality.py)。未修改原 FactReader、解析代码、日期规则、输入 manifest 或覆盖表。配置模板 `config/quality.example.json` 的空路径/日期会拒绝运行；本机实际配置 `config/quality.local.json` 已确认被 Git 忽略。

沿用 Python 3.11.15、JDK 17.0.19、PySpark/Spark 3.5.8；local[4]、Driver 4g、32 shuffle分区、UTC。同一 FactReader 上下文加载真实 Parquet 1次；事实、两种重复组、会话组和关联标签使用 MEMORY_AND_DISK 缓存，分析结束释放，Spark 正常停止。仅收回至多32个日期聚合、5个行为聚合或1行会话汇总；没有收回完整用户/session清单。标签明细没有另行持久化为事实。

成功人工轮耗时16.435秒，真实轮106.357秒（仅执行收据，不是性能基准）。真实运行新增产物采样高水位4,444,790,448 bytes（4.140 GiB），高于执行前低于3 GiB的粗估，但未超过5 GiB上限；最低可用559,899,410,432 bytes（521.447 GiB），高于150 GiB要求。累计预算同时覆盖新 synthetic、失败日志、临时文件和缓存落盘，每至多2秒检查。峰值内存 not_measured，未为测量额外运行。

## 可以说与不能说

可以说：本固定用户候选内存在明确字段相同的重复候选；按冻结假设，事件与金额的敏感性影响已量化；关联未造成膨胀或丢失；在本窗口、复合键和5000阈值下没有高频命中。统计事实可信度高，含义仍受输入范围限制。

不能说：候选都是误采集、B是清洗真值、1427.11是业务损失或收益、没有机器人、长跨度等于停留时长，或这代表平台总体。重复来源可能包括采集重发或真实重复行为，长跨度可能涉及标识复用等情况，均缺采集链路/会话生成机制/业务上下文证据，未作归因。候选重复对当前金额影响有限，保留主口径；长跨度属于后续解读会话时的限制，不新增本轮过滤规则。

工程无剩余缺口，本人解释未代验。下一项建议仅为 T1.3 正式指标层，不继续扩建质量平台。
