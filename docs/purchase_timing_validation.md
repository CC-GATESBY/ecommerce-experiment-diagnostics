# 11月15–17日购买记录核查

## 运行前固定的规则

本轮只定位四类解释：A原发布源已有形态；B固定用户抽样差异；C本地提取/解析/聚合丢失或重复；D本地问题排除后，交易真实发生与记录机制仍不能区分。分析窗口固定为[2019-11-14,2019-11-19)，UTC。既有源级profile只有日期总数、小时总数和全月行为数，没有日期×行为交叉计数，因此授权完整流式读取已有11月源一次、候选一次；SHA随读取计算，只输出5天汇总。扫描范围与分析范围分别记录。

直接复用rees46-user-sample-v1、seed20260916及原始user_id字符串，不限十月用户名单。九字段按原顺序长度编码的序列SHA核对同哈希范围，保留重复重数；金额沿用rees46-events-v1.0.1的标准库独立解析，仅amount_eligible汇总Decimal。全源和5%样本不要求总量相等、不乘20。先完成全文件结构、身份验证才能将空小时记为观测计数0；读取失败不出完成汇总。

重复候选检查仅针对候选窗口内purchase原九字段完全相同，SQLite本地计重；不删除、不注册新事实。小时集中度只报告有购买小时数、最高1小时/3小时占当天购买事件或金额比例，不设事后故障阈值。时间均为event_time，未生成ingestion_time。

敏感性是事后分支：完整11月30天为主；另一支暂不纳入15–17日，27日日均与十月31日日均比较，日期/星期组成未控制，不能代替主结果。历史分支仅移除15–17日的历史资格，不动当前日、不补其他日期；沿用7/14/21/28天、min3、median/MAD、1.4826、|score|>3且相对幅度≥10%。仅比较历史集合含这三天的后续日期；不足3点不计算中位数/均值/分数。检测中位数与描述性历史均值分列，不混用方向。旧告警与scope不改。
