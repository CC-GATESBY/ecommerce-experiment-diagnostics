# 本地小批量范围补充

记录日期：2026-09-16。依据：用户当前明确指令与本地 bootstrap；本补充优先于旧规划中相冲突的规模和执行顺序，v4 统计口径与质量要求保持不变。

1. **唯一主环境为本地。** MRC、Nectar、Spartan 不作为当前依赖，不登录或操作云资源。
2. **先工程样本，再分析样本。** 工程样本检查读写、解析与质量边界；分析样本须覆盖问题所需的完整观察窗口。
3. **全量不自动执行。** 全量双月或七个月处理均为可选扩展，须小批量验收后由用户明确决定，不作为首版完成条件。
4. **样本必须可追溯。** 记录实际规模、时间范围、采样方法、随机种子与 `scope_id`。文件头工程样本不能支撑总体行为、留存或长周期异动结论。
5. **分析样本优先保留完整轨迹。** 优先考虑跨完整观察窗口的固定用户样本。小输出不意味着来源下载或抽取扫描也小，下一轮先说明这些成本，不在本轮下载或抽取数据。
6. **只报告实际范围。** README、任务状态、报告和简历均使用实际运行记录，不套用数据集发布规模，不预填收益、性能或模型结果。
7. **三类证据隔离。** REES46 行为日志、人工模拟和 Criteo 公开实验分别处理，不连接两份数据的用户，不将离线证据写成线上业务效果。
8. **保留现有规划。** 三份 v4 文件继续使用；不复制另一套完整规划，不重排全部任务。

历史阶段 S0 已完成：独立 Git、指定 private 仓库、安全文件提交、push 与 SHA 核对。当时 T0.3 仅记录 Git 子项，安装、版本锁和 Spark 测试为 `not_run`。T0.1、T0.2 的既有结果保留，该历史限制不代替最新用户授权。
