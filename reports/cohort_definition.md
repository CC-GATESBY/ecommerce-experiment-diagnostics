# 固定队列：保留谁作为评价分母

**评价前置期已经出现用户的后续结果，应保留全部84,165名入组者，包括50,723名未返回者。** 同样的4,812名购买用户，除以固定名单得到5.7173%；只除以返回者得到14.3891%。差8.6718个百分点来自分母选择，不是策略带来的提升。本轮没有随机处理、A/A或效应注入。

| 业务问题 / 数量 | 实测 | 分母或解释 |
|---|---:|---|
| A. 前置期入组 N | 84,165 | 10月1–14日有合格事件的不同用户 |
| B. 结果期返回 R | 33,442 | 入组者中，10月15–28日有合格事件 |
| C. 未返回 N−R | 50,723 | 留在队列，未观察到的购买记0 |
| D. 结果期购买 B | 4,812 | 入组者中至少一条purchase |
| E. 全队列购买率 B/N | 5.7173% | 固定队列的后续购买结果 |
| F. 返回者购买比例 B/R | 14.3891% | 已返回这一条件下的购买比例 |

F可以回答一个有用的条件问题，但如果拿它代替E，就把“没有返回、因而未观察购买”的人从评价中移除了。未来策略本身也可能影响返回；按结果期活跃重新选人，会改变入组人群，不能再用它代表全部原入组者的结果。**本轮只建立观察队列，尚未证明任何实验效应。**

结果期才首次在当前观察范围出现、且不在前置名单中的用户有**57,527**人，单独记录，不加入分母，也不称真实新注册用户。金额只看固定队列：结果期10,630条购买事件、观测金额**3,499,563.53**，每入组用户**41.5798**；28个窗口日期计数/金额均允许，完整性`complete_observed`，未知金额用户0。金额是日志price的观测和，不是利润或财务收入。

## 窗口、字段与适用限制

本轮规则在真实计算前固定。队列版本 `rees46-pre-oct01-14-post-oct15-28-v1`，仅使用 `rees46_oct_user5_analysis_v1` 的 `metrics-month-01` 用户日表，事实来源 `month-v101-01`，主口径 `baseline_keep_all`。

前置期 `[2019-10-01T00:00:00Z,2019-10-15T00:00:00Z)` 至少有一条合格事件的用户全部入组；结果期 `[2019-10-15T00:00:00Z,2019-10-29T00:00:00Z)` 是否返回、购买或金额大小均不参与选择。结果期才出现的人不加入；10月29–31日不进入结果窗。所有边界均为UTC半开区间。

以前置期名单为左表，未返回者仍保留。在结果窗日期完整且计数允许时，他们的返回、购买标记及购买事件数是观测结构性0，不代表永久流失。购买用户数B不变：B/N回答全部入组用户后续有多少购买，B/R回答返回者中有多少购买。后者可以使用，但不能代替前者；两者差异是选择分母的结果，尚无随机处理或策略效果。

金额沿用原日志单位与Decimal(38,2)。合格无购买可为0；坏购买金额保留用户和购买标记，完整金额为NULL，并保留partial_observed/unknown。任一窗口日期金额阻断时，该窗口所有用户完整金额都暂停，另以window_amount_blocked标明；不按好金额用户重新筛人。缺失日期或计数阻断则拒绝整个队列生成。现有质量放行只说明本样本记录可用，不证明上游绝对完整。

逻辑队列表每用户一行；本地分为身份表（cohort_key、scope_id、原user_id）和数值表（同键及前后事件数、购买标记、金额、金额状态/坏值数/合法值数/缺金额用户日数、窗口金额放行）。cohort_key为版本前缀与原scope/user字符串长度编码后的SHA256，不含结果或run；它只是连接键，不是随机分组，也不因哈希就可公开。两表连接后恢复完整队列，用户级内容全部留本地，不生成用户×日期稠密面板。

这批用户只是十月目标用户概率5%的固定样本中，前置期已被观察到的人，不代表全平台新老用户。与[T3.4购物车方案](next_experiment_design.md)不同：该方案要求首次加购后24小时未观察到购买，再看后续24小时；本队列不要求加购、不排除前置期买家，统一看两个14天窗口。购物车历史率与Criteo基准均不作为本轮预期。
