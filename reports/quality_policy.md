# T1.2 重复候选与会话质量定义

版本 `rees46-quality-v1`，2026-09-17 在真实查询前冻结。只使用 FactReader 放行的 `month-v101-01`，scope `rees46_2019_oct_user5_fedd938409b5f836_20260916_v1`，分析序列 `rees46_fixed_users_20260916_v1`；观察窗口为 2019-10-01 至 10-31 UTC。解析契约 v1.0.1、日期规则 v1 均不改动。粒度仍是一条行为记录，购买事件不是订单。

## 重复候选键

规范化键包含原始九字段对应的完整业务信息：时间、行为、商品 ID、品类 ID、品类代码、品牌、价格、用户 ID、session。采用有类型的 struct，不用可能发生分隔符歧义的字符串拼接，也不用哈希碰撞作为同组依据。

- 时间：有效值使用已经解析的 UTC timestamp；无法规范化时保留原时间字符串及 missing/invalid 状态。
- 金额：有效值使用既有 Decimal(18,2)，不转浮点。解析为 null 时保留原价格字符串及 missing、invalid、nonfinite、precision、scale 状态；negative、zero 标记也进入键。`1.0` 与 `1.00` 可成为规范化候选，`bad-a` 与 `bad-b` 不会变成同一个 null 金额组。
- 行为、所有 ID、品类代码、品牌和 session：保持原字符串，包括前导零、大小写和空白；不 trim、不补造、不作模糊匹配。派生状态沿用原契约，不重新定义有效值。
- 不包含 source/run 运行信息或 parsed_at_utc。当前读取范围已由唯一登记批次固定；不跨 scope 判重。
- 对照键为原始九字段的完整 struct，只有原字段字符串逐项相同才同组。

对每个 n>1 的组分别报告：重复组数 1、涉及事件数 n、超额事件数 n−1。另按行为报告涉及的去重用户、购买候选事件，以及“每组留一条”的合格观测购买金额减少值。候选相同不证明采集重复：源数据没有足够的事件身份/采集链路证据确认哪些记录应删除。

## 会话定义

有效会话键为 `(user_id, user_session)`：用户 ID 通过现有校验，session 非 null 且非原契约定义的空/纯 ASCII 空白。缺失 session 事件单独统计并留在主表，不参与会话聚合；不同用户的相同 session 不合并。相同有效键可跨日，不切为 30 分钟会话。

记录每会话事件数、购买事件数、合格观测购买金额、首末 UTC 时间、观察到的日期数与 `last_time−first_time` 秒数。后者称“观察到的会话跨度”，不是停留时长。缺少观察窗外事件，跨度可能被月边界截断。

真实高频阈值固定为完整窗口内 **事件数 >5000**（5000 本身不命中）。仅为 v4 探索标记，不等于机器人、无效流量或删除依据；没有命中也不降低阈值。人工集成测试单独固定 >3 用于验证分支，不传入真实配置。

事件数和跨度分位数采用 Spark SQL `percentile_approx`，概率 `[0.5,0.9,0.99]`、accuracy=10000；属于近似分位数，参数对应约 1/10000 的相对误差控制，不承诺精确样本分位值。会话数、最大值及金额是精确聚合；不收回用户/session 明细。

## 关联及三种敏感性假设

候选组与有效会话各自每键恰好一行，再以左连接关联原明细。候选 struct 键使用 null-safe `<=>`；会话关联同时检查 session 有效性，不给空 session 添加共同标签。分别核对候选关联后、会话关联后、双标签后的全月及逐日事件数、行为数、去重用户、购买用户/事件及 Decimal 金额；不靠 DISTINCT 修补结果。

仅比较以下三个场景，均要求日期 count/amount 放行并保持同一范围：

| 场景 | 行选择 | 用途 |
|---|---|---|
| A baseline_keep_all | 全部 event_eligible 行 | 主口径，始终保留 |
| B hypothetical_one_per_duplicate_group | 规范化键每组一条；按原九字段 struct 的字典序选代表，完全相同的行任选一条不会改变逻辑值 | 独立敏感性分支，不回写事实 |
| C hypothetical_exclude_heavy_sessions | 只排除有效键下 >5000 的会话；无匹配会话标签（含缺失 session）仍保留 | 独立敏感性分支，不回写事实 |

不增加 B+C。每个场景分别重新计算全月与逐日去重用户，不能把逐日用户数相加。购买用户按合格购买行为去重，金额仅汇总 amount_eligible 的 Decimal；不能先筛购买行再算用户分母。以 A 为基线报告事件、用户、购买用户、购买事件及金额的绝对变化和相对变化 `(scenario−baseline)/baseline`；基线为 0 时相对值为 null，reason=`baseline_zero`。比例展示为小数、保留 12 位，不影响金额精确比较。日期即使被假设分支移除全部行，也从已确认的基线日期集合显式补出场景零行，标为该假设的移除结果，不推断源数据缺日。

B/C 是处理假设的敏感性，不是清洗真值、业务损失或优化收益，不登记为正式输入。主事实不修改，局部标签/组统计仅留独立本地目录；对 Git 只提交无用户/session 标识的汇总。
